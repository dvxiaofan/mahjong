# 联网消息协议

- **协议版本**：1
- **实现位置**：`src/protocol.ts`
- **传输要求**：JSON 文本；处理器不依赖具体 WebSocket/HTTP 库
- **状态权威**：服务端 `AuthoritativeRoom`
- **实际端点**：同源 `/ws`（生产应使用 WSS）

## 1. 安全边界

- 客户端永远不提交可信座位，座位由已认证的连接上下文注入；
- 客户端只提交动作意图，不提交手牌、牌墙、番数、分数或结算；
- 每个动作携带 `requestId` 和 `expectedRevision`；
- 服务端对相同请求做幂等处理，对过期修订号返回最新座位快照；
- 快照使用 `projectStateForSeat()`，只暴露本座暗手和合法动作；
- 对手暗手、牌墙顺序、私有听口及具体响应选择不会进入协议消息。

## 2. 客户端消息

所有消息都包含：

```json
{
  "protocolVersion": 1,
  "requestId": "client-generated-id",
  "type": "message-type"
}
```

| 类型 | 用途 | 关键字段 |
|---|---|---|
| `hello` | 协议握手 | 无 |
| `create-room` | 创建房间并成为房主 | `roomId`、`displayName`、可选 `password` / `maxRounds` |
| `join-room` | 加入或恢复房间 | `roomId`、`displayName`、可选 `seatPreference` / `resumeToken` |
| `list-rooms` | 获取公开房间列表 | 无 |
| `leave-room` | 主动离开并释放座位 | 无 |
| `set-trustee` | 主动开启/关闭本座 AI 托管 | `enabled` |
| `get-snapshot` | 请求当前座位快照 | 无 |
| `submit-action` | 提交规则动作意图 | `expectedRevision`、不含座位的 `action` |
| `start-next-round` | 局间请求下一局 | `expectedRevision` |
| `ping` | 保活/延迟测量 | `nonce` |

动作意图示例：

```json
{
  "protocolVersion": 1,
  "requestId": "action-42",
  "type": "submit-action",
  "expectedRevision": 17,
  "action": { "type": "discard", "tile": "m5" }
}
```

## 3. 服务端消息

| 类型 | 用途 |
|---|---|
| `welcome` | 握手成功、房间和当前修订号 |
| `room-joined` | 入座/观战成功，返回恢复令牌、房间视图和隐私快照 |
| `room-left` | 主动离开成功 |
| `room-list` | 不含密码摘要和恢复令牌的公开房间列表 |
| `trustee-updated` | 托管状态更新后的大厅视图 |
| `snapshot` | 当前连接座位的完整隐私安全视图 |
| `action-result` | 权威动作接受/拒绝结果 |
| `event-batch` | 动作接受后的座位可见事件 |
| `pong` | 对应客户端 nonce |
| `error` | JSON、版本、入座或生命周期错误 |

## 4. 修订号与幂等

1. 房间从 revision 0 开始；
2. 每个成功动作或开始下一局使 revision 加 1；
3. `expectedRevision` 不等于当前 revision 时返回 `stale-revision`；
4. 同一 `requestId` + 相同内容返回第一次结果，不重复执行；
5. 同一 `requestId` + 不同内容返回 `request-id-conflict`；
6. 客户端收到过期错误后应使用随响应返回的新快照更新本地状态，再决定是否重试新动作。

## 5. 运行时校验

`parseClientMessage()` 会拒绝：

- 损坏 JSON；
- 非对象消息；
- 不支持的协议版本；
- 空或过长请求 ID；
- 非法修订号、牌名、动作类型、座位偏好；
- 空房间名/昵称及超长字段。

即使客户端在动作对象中附带 `seat`，解析器也会将其丢弃，由连接上下文重新注入座位。

## 6. 断线、恢复和托管

- 网络断开与主动 `leave-room` 不同：断开后参与者、座位和恢复令牌仍保留；
- 玩家断开后立即进入同座 AI 托管，观战者断开不触发动作；
- 新连接通过 `join-room.resumeToken` 恢复身份，成功后令牌立即轮换，旧令牌失效；
- 默认断线保留 2 分钟，超时后释放参与者和座位；
- 默认出牌时限 30 秒、响应时限 12 秒；
- 在线玩家在响应阶段超时固定执行 `pass`，其他超时使用同座 AI 的合法动作；
- 主动托管、断线托管和超时动作全部进入权威房间审计及修订号序列。

## 7. 服务端传输

- `server/server.ts` 使用 HTTP + `ws` 提供真实传输；
- HTTP 同时托管 `dist-web/` 页面；
- 房间变更后，服务端分别为每条连接生成大厅更新和对应隐私快照，禁止复用同一玩家快照广播；
- 服务端状态原子写入权限为 `0600` 的 JSON 文件；
- 进程重启后所有旧连接标记为断线，玩家必须使用恢复令牌重新绑定。
