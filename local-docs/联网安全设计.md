# 联网安全与反作弊设计

- **日期**：2026-09-05
- **实现**：`src/security.ts`、`src/gateway.ts`、`src/room.ts`
- **状态**：M4.6 已实现并通过自动化测试

## 1. 信任边界

- 服务端持有完整牌墙、所有暗手、随机种子、番数和分数；
- 客户端只提交不含可信座位的动作意图；
- 连接 ID 在服务端绑定参与者、房间与座位；
- 每个座位得到独立投影，观战者得到全公开投影；
- 客户端计算出的胡牌、番数、支付和牌墙状态全部不可信。

## 2. 已实现控制

| 风险 | 控制 |
|---|---|
| 超大消息/内存消耗 | 默认消息上限 16 KiB |
| 请求洪泛 | 默认 10 秒最多 60 个请求的滑动窗口 |
| 重复非法动作 | 违规计数，默认 5 次后封禁 60 秒 |
| 请求重放 | `requestId` 幂等缓存 |
| 同 ID 篡改 | `request-id-conflict` |
| 并发旧动作 | `expectedRevision` 与房间 revision 比对 |
| 座位伪造 | 忽略动作中的 seat，由连接上下文注入 |
| 跨房间连接 | 一个连接只能绑定一个参与者 |
| 密码泄露 | 随机盐 + SHA-256 摘要；公开视图不含摘要 |
| 恢复令牌重放 | 安全随机令牌，恢复成功后立即轮换 |
| 观战作弊 | 全公开投影且禁止提交动作 |
| 日志泄密 | 安全审计仅记录类别与短详情，不保存原始载荷 |

## 3. 安全审计

`SecurityGuard.getAuditSummary()` 输出：

- 总违规次数；
- 连接、时间、违规类型和脱敏详情；
- 当前临时封禁连接及解封时间。

审计中不存储：房间密码、恢复令牌、完整消息体、暗手、牌墙或个人文本内容。

## 4. 默认参数

```text
消息体上限          16 KiB
请求窗口            10 秒
窗口请求上限        60
违规封禁阈值        5 次
临时封禁            60 秒
断线座位保留        2 分钟
出牌超时            30 秒
弃牌响应超时        12 秒
```

所有参数均可在服务端构造时覆盖，便于测试和部署环境调优。

## 5. 剩余部署责任

- 生产环境必须使用 TLS/WSS；
- 在反向代理层设置连接数、IP 级限流和请求体限制；
- 恢复令牌只通过当前连接返回，不写入访问日志；
- 定期清理已过期房间、断线参与者和幂等缓存；
- 如果未来加入账号系统，应将参与者身份绑定到经过验证的账号会话；
- 需要根据实际流量设置审计保留和告警策略。
