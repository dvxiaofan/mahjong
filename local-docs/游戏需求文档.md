- **目标**：把约定麻将规则实现为可玩的数字麻将，支持本地 1 人 + 3 AI 对战和服务端权威的联网房间。

## 1. 可行性结论

本玩法已经实现为浏览器游戏，采用以下分层方案：

1. 浏览器端本地单机版：1名玩家 + 3名 AI；
2. 将洗牌、发牌、摸牌、发财补牌、鸣牌、听牌判断、报嘴、胡牌和结算写成独立的纯规则引擎；
3. UI 负责展示状态和提交动作；只读解释复用规则引擎，联网动作仍由服务端校验；
4. 联网房间通过 HTTP/WebSocket 服务同步，由服务器校验规则并保存权威状态。

难点不在普通麻将牌型，而在以下自定义机制：

- 发财从手牌中分离，并从墙尾补牌；
- 三家通碰，需要处理弃牌响应和冲突；
- 报嘴后锁定听口，且摸到胡牌张必须胡；
- 明杠、补杠、暗杠的不同结算时机；
- 荒庄时所有杠分作废，已即时支付的补杠分退还；
- 一炮多响及同一弃牌的竞争按弃牌者下家起、沿逆时针依次处理，前位玩家过牌后继续看下一位。

这些机制适合用明确的有限状态机实现，不建议把规则散落在界面代码中。

## 2. 产品范围与完成情况

### 2.1 本地单机版（已实现）

**目标**：能完整打一局，并严格按定稿规则结算。

- 运行方式：浏览器本地运行；
- 玩家：1名人类玩家 + 3名 AI；
- AI：休闲、标准、进阶三档可解释启发式策略；
- 存储：自动保存当前本地牌局，支持刷新恢复、事件记录和逐步回放；
- 当前范围不包含：账号、自动匹配、支付、排行榜、广告、社交系统。

### 2.2 本地体验完善（已实现范围）

- 三档 AI 策略、决策解释和候选动作；
- 事件提示、键盘操作和桌面/移动端适配；
- 牌局回放和逐步复盘；
- 本局结算、支付与杠分流水；
- 参考素材裁切的 PNG 牌面、发财牌面展示；
- 新局重新洗牌、仅有摸牌或过牌动作时自动推进；
- 四家掷骰定首庄、赢家接庄和开门信息展示；
- 顶部牌桌状态栏与随内容增高的玩家区域，手机手牌在自身区域内滚动；
- 出牌来源、牌面和各家响应进度集中提示，动作按钮整合到我方手牌下方；
- 新弃牌在中央悬浮放大，确认无人响应后移动并缩小到出牌者弃牌区，兼容回放、重连和减弱动态效果；
- 胡牌后四家亮出完整终局，胡、碰和各类杠在中央放大提示；
- 公开出牌与碰杠胡语音，主静音、两路音量/开关、试听和偏好保存；
- 终局四面子一将分组；自己的胡牌条件与剩余牌按需解释（已完成浏览器验收）。

### 2.3 联网版（已实现）

- 创建/加入房间；
- 服务器权威洗牌和规则校验；
- WebSocket 实时同步；
- 掉线重连和托管；
- 房间密码、观战、多局累计分和本场对局结果。

联网版不是简单地把本地版加一个网络层，需要单独设计服务器状态、并发动作和作弊防护。

## 3. 已确认的规则模型

### 3.1 牌库

按每种牌 4 张计算，共 120 张：

- 万、筒、条：108 张；
- 红中、白板、发财：12 张；
- 无风牌、无花牌。

红中、白板为普通牌：可以碰、明杠、暗杠、进入牌型，不加番。
发财为特殊宝牌：

- 起手或自己摸到后，亮牌放在手牌旁；
- 每张发财 +1 番；
- 不碰、不杠、不参与牌型；
- 从墙尾（起牌顺序的反方向）补摸一张，保持正常手牌数量；
- 四张发财作为四张独立宝牌保留，不算杠。

### 3.2 鸣牌和杠

- 吃：禁止；
- 碰：上家、下家、对家三家都可以碰；
- 明杠：暗藏三张，别人打出第四张；
- 补杠：已有碰牌，之后自己摸到第四张；
- 暗杠：四张均由自己起牌或摸到；
- 摸牌前暗杠先从墙尾补牌，再完成本回合正常摸牌；连续暗杠逐次补牌，不重复或省略正常摸牌；
- 发财不能参与任何杠；
- 无抢杠胡；
- 补杠即时结算，明杠和暗杠终局结算；
- 荒庄时所有杠分作废，已即时支付的补杠分退还。

### 3.3 胡牌和番种

- 胡牌结构：标准 4 面子 + 1 将；
- 碰出的面子计入牌型；
- 同种牌在暗手与碰杠中的实体总数不得超过四张；胡牌、听牌和报嘴判断均排除第五张同牌；
- 碰碰胡 +1 番；
- 清一色 +1 番；
- 发财每张 +1 番；
- 无起胡番要求；
- 无发财只能自摸；
- 至少 1 张发财才可以点炮；
- 杠后补牌胡牌算自摸，当前没有额外“杠上开花”番。

### 3.4 报嘴

- 有至少 3 张发财且当前听牌时，可以选择报嘴；
- ≥3张发财未报嘴时可以自摸，但不能点炮；
- 不报嘴不会失去继续摸打、碰杠和换听的资格；
- 报嘴后听口锁定；
- 报嘴后不能换听、碰或杠；
- 非胡牌摸牌必须原张打出；
- 摸到胡牌张必须胡；
- 报嘴后摸到发财，照常亮牌并补牌，补牌成胡时胡牌。

### 3.5 结算

- 自摸：三家各付 `1 + 番数`；
- 点炮：点炮者付 `1 + 番数`；
- 补杠：被碰者即时付 1 分；
- 暗杠：终局三家各付 1 分；
- 明杠：终局点杠者付 1 分；
- 一炮多响及同一弃牌竞争：按弃牌者下家起、沿逆时针依次处理，只认第一位实际声明动作的玩家；
- 荒庄：平局，所有杠分作废，已即时支付的补杠分退还。

## 4. 推荐技术方案

### 4.1 前端

- TypeScript；
- React + Vite；
- CSS 或轻量组件方案；
- 响应式布局，优先支持桌面浏览器，兼顾手机横屏。

当前牌面组件直接引用 `web/public/tiles/` 下的本地 PNG，2026-09-06 已替换原 SVG 绘制方案；素材中额外的风牌/花牌图片不进入规则引擎的 120 张牌库。

### 4.2 规则引擎

规则引擎应是独立 TypeScript 模块，不依赖 React 或浏览器 API：

- 输入：当前状态 + 玩家动作；
- 输出：新状态 + 事件列表 + 可用动作；
- 使用确定性随机种子，便于测试和复盘；
- 所有动作先经过合法性校验；
- UI 不允许直接修改牌墙、手牌或分数。

### 4.3 数据结构建议

```text
GameState
├── players[4]
│   ├── concealedTiles
│   ├── exposedMelds
│   ├── fortuneCount
│   ├── mouthDeclared
│   ├── lockedWaits
│   ├── gangRecords
│   └── score
├── wall
│   ├── drawIndex
│   ├── replacementIndex
│   └── remainingCount
├── discards[4]
├── currentSeat
├── phase
├── pendingDiscard
├── pendingClaims
├── dealerSeat
└── eventLog
```

推荐将发财数量单独建模为 `fortuneCount`，不要把发财混入普通手牌数组。

### 4.4 动作类型建议

```text
DRAW
DISCARD
PASS
PONG
CONCEALED_KONG
EXPOSED_KONG
SUPPLEMENT_KONG
DECLARE_MOUTH
WIN_SELF_DRAW
WIN_DISCARD
```

发财的处理可以作为摸牌后的自动事件：

```text
DRAW -> DRAW_FORTUNE -> MOVE_FORTUNE_ASIDE -> REPLACEMENT_DRAW
```

## 5. 牌局状态机

以下是逻辑处理阶段；实际引擎将其收敛为 `awaiting-draw`、`awaiting-discard`、`claiming`、`finished`、`drawn` 五种 phase：

1. `DEALING`：洗牌、发牌、处理起手发财补牌；
2. `READY`：确定庄家和起手顺序；
3. `DRAWING`：当前玩家从正常端或补牌端摸牌；
4. `FORTUNE_REPLACEMENT`：处理发财和补牌链；
5. `SELF_ACTION`：自摸、暗杠、补杠、报嘴或出牌；
6. `DISCARD_RESPONSE`：其他玩家对弃牌进行胡、碰、明杠或放弃；
7. `RESOLVE_CLAIM`：按优先级及座位顺序处理竞争动作；
8. `WIN_SETTLEMENT`：胡牌结算；
9. `DRAW_SETTLEMENT`：荒庄处理；
10. `ROUND_END`：确定下一局起手者。

报嘴玩家需要额外约束：

- 不生成碰、杠和换听动作；
- 自摸非胡牌时只能生成“原牌出牌”；
- 对符合听口的自摸胡张生成“必须胡”动作；点炮生成“胡/过”动作；
- 报嘴后摸到发财时，先完成发财补牌，再判断补牌是否胡。

## 6. AI 设计

MVP 的 AI 可以分三层：

1. **合法性层**：永远不执行非法动作；
2. **成牌层**：计算向听数、可进牌和基本番数；
3. **风险层**：根据其他玩家的碰牌、报嘴和弃牌，减少危险出牌。

第一版不必实现复杂机器学习。建议先实现：

- 优先保留有效搭子；
- 优先完成清一色或碰碰胡倾向；
- 有 3 张发财且听牌时自动报嘴；
- 报嘴后严格摸打；
- 能胡时按规则自动胡；
- 碰、杠、明杠按简单收益策略选择。

AI 的手牌选择必须调用同一套规则引擎，不能另写一套会产生不一致的胡牌判断。

## 7. UI 需求

### 7.1 牌桌

- 显示自己的手牌、发财区、碰牌和杠牌；
- 显示三名对手的座位、剩余手牌数量、发财数量和已报嘴状态；
- 任意玩家胡牌后，四家和观战者均可看到四家终局手牌、碰杠与发财；胡牌张单独标识但不重复添加，回放到胡牌前及新一局继续隐藏对手暗牌；
- 显示四家的弃牌区；
- 牌墙剩余数量、当前阶段、行动玩家和待响应牌显示在顶部独立状态栏；
- 玩家区域按实际内容高度排布，弃牌、碰杠、发财或报嘴提示增多时不能遮挡其他区域；
- 桌面保持四方座位关系，820px 以下将对家、两侧和我方分行；
- 手机手牌允许局部横向滚动，页面本身不应横向溢出；
- 30 种牌面图案须与实际牌值一致；三、五、七条错位已在 M10 修正，M11 增加人工核对后的图片内容指纹；后续替换素材同步核对图案、裁切记录和图片缓存；
- 新出牌显示实际牌面、相对座位和座位号，区分出牌者、待响应与已响应玩家；
- 胡、碰和各类杠在中央悬浮放大提示，包含动作玩家及牌面；不参与布局、不拦截点击，手机长牌桌跟随可见区域中央；
- 新弃牌在中央悬浮放大，不撑高任何玩家模块；等待响应时持续显示，全部过牌后移动并缩小到来源玩家的实际弃牌位，归位前不重复显示小牌；
- 被碰、杠、胡走或本局结束时立即清理旧出牌浮层，较早同牌保持原样；
- 动画不参与规则推进，快速连续出牌以最新状态为准，回放和重连快照静态展示，减弱动态设置禁用牌面动画。

### 7.2 操作

- 摸牌、出牌；
- 本地玩家唯一合法动作为摸牌或过牌时自动执行；同时存在报嘴、暗杠等选择时等待玩家；
- 可用动作按钮：胡、碰、杠、暗杠、报嘴、过；
- 动作按钮位于我方手牌下方，提示与待响应牌就近展示；按钮至少 44px 高，窄屏换行；
- 提交期间关闭动作与手牌操作，联网等待对应请求确认；拒绝后可重试，确认超时则重连同步，不重复发送；
- 断线、等待入座、托管、回放和观战不能手动出牌；重连获得新房间快照后才恢复操作；
- 报嘴时展示当前听口，并提示“报嘴后不能换听”；
- 只展示规则引擎生成的合法操作，报嘴后不再提供碰、杠或换听操作；
- 发财、补牌、杠分和结算显示事件提示。

### 7.3 结算页

- 胡牌牌型及实际四面子一将分组；区分顺子、刻子、碰、明杠、暗杠、补杠，优先匹配碰碰胡计番；
- 发财数量和发财番；
- 其他番种；
- 自摸/点炮信息；
- 各项杠分；
- 每个玩家本局净得分和累计分数；
- 荒庄时明确显示不结算规则。

---

### 7.4 声音与规则解释

- 声音默认静音，由明确操作开启；语音和音效独立开关、音量与试听，偏好保存在本地。
- 只播新增公开事件对应的本地短音频，不朗读私有摸牌、听口或自由事件文字。
- 初始快照、回放、重连、新局和身份切换不补播历史；静音、后台和新事件取消旧播放，声音失败不影响牌局。
- 我方操作区提供默认收起的“胡牌条件”；展开后才计算自己的分组和剩余牌，观战不提供私有分析。
- 区分未成牌、无发财、报嘴和锁定听口限制，以及未摸牌、待补牌、碰后、他人回合、自己弃牌和已响应阶段。
- 原因复用胡牌规则，回放、断线、提交等待单独提示；分组不额外添加摸牌或弃牌，也不制造第五张同牌。
- 部分整理明确标注为“一种整理方式”，与正式胡牌判定区分。

## 8. 测试重点

规则引擎至少需要覆盖：

- 120 张牌数量和每种牌数量；
- 全部 30 种牌面的实际图片内容、牌值、名称、排序与裁切坐标对应；
- 全部 29 种普通牌在四座位的摸打、碰、三类杠、自摸与点炮，对应到同一张牌；
- 动作前后全桌仍为 120 张且每种四张，手牌数与摸牌、出牌、补牌及终局阶段一致；
- 暗手与碰杠合计四张后不再听第五张，合法第四张仍可胡；
- 摸牌前暗杠、连续暗杠、补牌后报嘴与正常摸牌，区分普通自摸和杠上开花；
- 普通摸牌与发财、杠后补摸的事件文案对应实际来源；
- 起手发财和连续发财补牌；
- 发财不参与胡牌、不允许碰杠；
- 三家通碰；
- 明杠、补杠、暗杠的合法性；
- 别人打出的第四张不能补杠；
- 无发财点炮被拒绝；
- 有发财可以点炮；
- 3 张发财听牌但未报嘴可以自摸、不能点炮；
- 报嘴后听口锁定；
- 报嘴后不能碰杠；
- 报嘴后摸非胡牌必须原张打出；
- 报嘴后摸到胡牌必须胡；
- 报嘴后摸发财并补牌成胡；
- 碰碰胡、清一色、发财番数叠加；
- 自摸、点炮、补杠、明杠、暗杠结算；
- 荒庄时杠分处理；
- 无抢杠胡；
- 一炮多响按弃牌者下家起、沿逆时针依次处理，只认第一位实际声明动作的玩家；
- 牌墙耗尽和补牌位耗尽。

建议为每个复杂牌局保留事件日志，使失败案例可以重放。

## 9. 已确认的规则与产品决策

初版草案中的待确认事项已经由规则定稿和实施台账解决，不再作为开发阻塞项：

| 事项 | 当前约定 |
|---|---|
| 起手与庄家 | 庄家 14 张，其余 13 张；首局四家比骰，并列加赛；后续赢家接庄，荒庄默认留庄 |
| 骰子与开门 | 两骰总点映射牌墙方位；每边 15 墩，每墩 2 张，按逆时针起牌 |
| 补牌来源 | 发财与杠后补牌共用墙尾；补到发财继续补牌；无牌可补立即荒庄 |
| 摸牌前暗杠 | 暗杠补牌不能替代本回合正常摸牌；正常摸到的胡牌张按普通自摸记录 |
| 实体牌上限 | 听胡判定合并暗手与碰杠中的牌数，同一种牌最多四张 |
| 报嘴约束 | ≥3 财且听牌可报嘴；锁定听口，不能碰杠；非胡牌补牌原样打出，自摸胡张必须胡 |
| 弃牌竞争 | 从弃牌者下家起逆时针判定；前位过牌后继续看下一位；同一窗口内可先报嘴再胡或过 |
| 牌型与番种 | 仅标准 4 面子 + 1 将；清一色排除红中/白板；碰杠本身不另加番 |
| 放弃胡牌 | 报嘴后自摸不可拒、点炮可拒；未报嘴按发财数量限制点炮资格，其余合法胡牌可放弃 |
| 荒庄 | 平局；所有杠分作废，已即时支付的补杠分退还 |
| 产品形态 | 浏览器本地对战 + 联网房间；AI 为休闲、标准、进阶三档 |

详细决策见 [开发实施计划.md](./开发实施计划.md) 的决策台账。
