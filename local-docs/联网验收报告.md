# M4 联网验收报告

- **验收日期**：2026-09-05
- **范围**：多局会话、权威房间、协议、房间生命周期、重连/托管、安全、WebSocket 与浏览器客户端
- **结论**：M4 验收通过

## 1. 四连接协议验收

自动化测试使用四个独立连接和一个观战连接完成一整局，并持续检查：

- 每个玩家快照只有自己的暗手，另外三家均为公开视图；
- 观战快照四家全部为公开视图且没有合法动作；
- 所有动作只提交意图，座位由连接身份注入；
- 弃牌响应阶段两条同修订号命令并发到达时，只接受第一条，第二条收到 `stale-revision`，使用新快照后可继续；
- 中途断开一个玩家后，使用一次性恢复令牌绑定新连接并继续；
- 第一局结束进入局间阶段，通过协议成功开始第二局；
- 整个流程在动作上限内完成，无隐私字段泄漏。

## 2. 真实 HTTP/WebSocket 验收

`server/server.test.ts` 使用真实端口和 `ws` 客户端验证：

- HTTP 返回构建后的页面；
- `/ws` 接收协议 JSON 文本并拒绝二进制消息；
- 创建和加入房间后，其他连接收到大厅和各自快照广播；
- ping/pong 可用；
- 断开后可在新 WebSocket 上恢复身份；
- 服务关闭时原子保存注册表，状态文件权限为 `0600`；
- 新服务进程读取状态后，原玩家可继续使用恢复令牌进入原座位。

## 3. 浏览器验收

- 页面提供“本地对局 / 联网对战”切换；
- 联网大厅支持创建、加入、密码、玩家/观战身份和房间列表；
- 房间内显示局数、revision、参与者、房主、在线/托管状态和累计状态；
- 未满四人时客户端不开放动作，服务端也返回 `room-not-ready`；
- 联网动作直接提交给服务端，不在浏览器本地计算规则；
- 刷新页面后使用本地保存的恢复令牌自动重连；
- 桌面和 390px 宽度无页面横向溢出，新页面日志无错误。

## 4. 自动化基线

```text
npm run check             引擎、页面、服务端类型检查通过
npm test                  25 个文件 / 125 个测试通过
npm run test:acceptance   6 个本地规则场景通过
npm run build             引擎、页面、服务端构建通过
```

## 5. 运行方式

```bash
npm run build
npm start
```

默认地址：

- 页面：`http://127.0.0.1:8787`
- WebSocket：`ws://127.0.0.1:8787/ws`
- 状态文件：`./data/rooms.json`

可使用 `PORT`、`HOST`、`MAHJONG_STATE_FILE` 环境变量覆盖。

## 6. 部署边界

- 当前服务是单 Node.js 进程；生产横向扩容需要共享房间路由/持久化；
- TLS/WSS、IP 级限流、日志采集和备份由部署层负责；
- 状态文件包含牌墙、暗手、密码摘要和恢复令牌，只能保存在服务端受限目录；
- 生产部署、CI、健康检查和回滚在 M5 完成。
