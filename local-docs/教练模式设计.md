- **日期**：2026-11-15
- **计划编号**：M15（M14 其余部分保持暂停）
- **依据**：用户 2026-11-14 的需求与三项选择；前期分析与探针数据见 `~/Documents/GoogleDrive/ClaudeCode/mahjong-概率助手应用分析/`（报告第 9 节）

**实施更新（2026-11-15）**：用户确认线框后已完成 PC Web 第一版。风险与听牌数字来自三档拟合模型，只读取 `GameView` 公开信息；训练 1440 局、留出 600 局，三档留出校准均通过。`npm run coach:fit` 可重跑采样、训练、校准并生成系数文件。

## 1. 目标

用户原话：想加一套教程类玩法，没轮到自己时也提醒风险概率，学习更好地打我们这套规则，提升自己的能力。

已确认的三项选择：

| 问题 | 选择 |
|---|---|
| 轮到自己时给不给答案 | **先自己打，再点评**；出牌前只标风险 |
| 用在哪些对局 | **只在本地对局** |
| 局后复盘 | **这期不做** |

成功标准：

1. 打开教练后，任何时刻都能看到三家各自「能不能胡我的牌、多大可能已听牌」，以及自己手里哪几张牌危险。
2. 显示的百分比对当前 AI 对手经过留出集校准（验收界限见第 7 节），不是凭感觉的档位。
3. 每次自己出牌后，能看到这手和教练的差别（向听、进张、风险），不需要翻记录。
4. 关闭教练时，本地对局与现在完全一致；联网对局不受影响。

## 2. 范围

**做：**

- 本地对局的教练开关（默认关，选择记在本机）。
- 右侧栏教练面板，三种内容：局势、出牌风险、出牌点评。
- 手牌上的风险角标；高风险牌出牌前确认一次。
- 按我们规则标定的风险模型，三档 AI 难度各一套系数，附可重跑的拟合脚本。

**不做：**

- 联网房间里的教练（需要只读 `GameView` 的适配和协议改动，且概率对真人不准）。
- 局后独立复盘页、固定剧本式教程（R-04、R-05 后来以教程模式和终局整局点评落地，不扩展教练为通用复盘页）。
- 碰、杠、报嘴、胡要不要的建议；面板在这些时刻只说明「本期教练不点评」。
- 让 AI 自己使用风险模型（2400 局 A/B 没有显示收益）。
- 回放中的教练。回放时面板不显示。

**不改：** 规则、计分、AI 出牌、联网协议、存档格式。

## 3. 用户看到什么

### 3.1 开关

本地对局的开始面板和牌桌上方工具栏各有一个「教练模式」开关，读写同一份本机偏好（`play-mahjong.coach.v1`）。对局中可以随时开关。

### 3.2 面板位置

宽屏（≥1200px）放在右侧栏顶部、动态列表之上；面板内容超出时栏内滚动，不改变牌桌和手牌坞的尺寸与位置。1200px 以下是默认折叠的一行摘要，点开查看。

一局结束后，结算面板接管右栏；教练面板只保留最后一条出牌点评（如果有），收成一张紧凑卡片放在结算上方。

### 3.3 局势（没轮到自己出牌时）

每个对手一行，按「下家 / 对家 / 上家」：

| 对手状态 | 显示 |
|---|---|
| 0 张发财 | 「没有发财，不能接炮」+ 听牌概率 |
| 1–2 张发财 | 「能接炮」+ 听牌概率 + 副露数 |
| ≥3 张发财、未报嘴 | 「要先报嘴才能接炮（少见）」+ 听牌概率 |
| 已报嘴 | 「已报嘴，听牌中」，重点样式 |

下面列出自己手里当前风险最高的至多 3 张牌（风险 ≥1% 才列），每张带百分比和一句主要原因；都不到 1% 时显示「手里暂时没有危险牌」。

### 3.4 出牌风险（轮到自己出牌时）

- 手牌上风险 ≥5% 的牌在右上角加点位：一般风险为黄铜金，≥10% 为珊瑚色。按用户确认的线框，角标不写百分比，也不改变牌面尺寸或手牌位置；百分比放在右栏列表和确认按钮里。读屏名称仍带完整风险。
- 面板按风险从高到低列出手里每种牌：百分比、主要原因（例如「对家碰了 2 组」「牌墙只剩 20 张」「这张对家打过」）。
- 这一步**不显示**教练会打哪张。
- 打风险 ≥10% 的牌时拦一次：点牌后不直接打出，出牌按钮显示「打出五筒 · 放炮约 12%」，再点才打出；Esc 或点别的牌取消。已经开着「先选牌再确认」的设备上，只是在原有确认按钮上加这段风险文字。
- 自己已报嘴（只能打刚摸的牌）时没有选择，面板只保留局势。

### 3.5 出牌点评（自己打完后，保留到下次轮到自己出牌）

并排显示「你打的」和「教练会打的」：向听、进张数、放炮风险。下面一句差异说明：

| 情况 | 文案 |
|---|---|
| 相同 | 和教练一致 |
| 教练的牌进张更多或向听更好 | 教练会打 X：进张多 k 张（或：不退向听） |
| 教练为了安全换牌 | 教练会打 X：进张少 k 张，放炮风险从 a% 降到 b% |
| 你的牌更安全但进张更少 | 你选了更安全的牌，进张少 k 张 |
| 这张被胡了 | 这张放炮了，当时估计风险 a% |

文案只陈述差异，不写「打错了」。原因：教练的换牌规则只验证过「当步放炮更少」，没验证过整局得分更高（见第 8 节）。

### 3.6 说明文字

面板底部固定一行：「概率按当前 AI 难度与公开信息估算；对真人打法不保证」。百分比不到 1% 显示「<1%」，其余取整。

## 4. 教练怎么选牌

1. 用现有 `rankStrategicDiscards` 得到按策略分排序的候选，第一名记为牌效首选。
2. 取「与最佳向听相同、进张数与最多者相差 ≤2」的候选为接近最佳集合。
3. 若牌效首选在集合内，且集合里有牌的风险比它低 ≥2 个百分点，教练改选集合里风险最低的那张；否则维持牌效首选。

探针数据（600 局留出种子，进阶 AI，只看当步）：这条规则改掉 2.3% 的出牌，放炮少 10.2%，每次换牌平均少 0.35 张进张。

## 5. 风险模型

### 5.1 输出

- **放炮风险**：对手里每种牌，估计「打出后至少有一家能胡」的概率。逐家算，再按 `1 − Π(1 − p)` 合并。
- **听牌概率**：对每个未报嘴的对手，估计其已听牌的概率。

### 5.2 输入（全部是公开信息）

模型函数的参数是 `GameView`，拿不到对手暗手和牌山顺序。

逐家风险的特征：

| 特征 | 取值 |
|---|---|
| 对手资格 | 已报嘴 / 1 财 / 2 财 / ≥3 财未报嘴 |
| 对手副露数 | 0 / 1 / 2 / 3+ |
| 牌局进度 | `1 − min(牌墙剩余, 66) / 66`，及其平方 |
| 牌的类别 | 中白 / 幺九 / 二八 / 三七 / 四五六 |
| 是否该家现物 | 是 / 否 |
| 该家同花色弃牌数 | 0 / 1 / 2 / 3+ |
| 这张牌已见张数 | 0–3（自己手里其余 + 四家牌河 + 副露） |
| 交互项 | 现物 × 已报嘴；进度 × 有副露 |

0 财的对手不进模型，风险恒为 0（规则保证）。探针里试过的「筋」和「该家有同花色副露」影响接近零（×0.91、×1.07），不纳入。

听牌概率用查表：`发财数（0 / 1 / 2 / ≥3）× 副露数 × 牌墙段（每 6 张一段）`。发财数必须分开：AI 一旦 ≥3 财且听牌就会报嘴，所以「≥3 财却没报嘴」的对手几乎都还没听牌，和 1–2 财的对手不是一回事。样本不足 200 的格子取同一行最近的有效牌墙段；整行都不足时不显示该家的听牌概率。已报嘴的对手直接显示「听牌中」。

### 5.3 系数从哪来

拟合脚本用现有 AI 自对弈：每次出牌，对手里每种候选牌 × 每个有财对手记一条样本，特征取公开信息，标签取真实暗手（这张牌该家能不能胡，含「现报嘴再胡」）。逻辑回归加 L2 正则。

三档难度（休闲 / 标准 / 进阶）各拟合一套，因为探针里标准档套用进阶档系数会高估约 15%。脚本把系数、听牌表、所用 AI 策略编号和留出集校准结果写进一个生成的源文件，文件入库；脚本固定种子，可重跑复现。

每档训练 1440 局、留出 600 局。每档从训练集最多采样 500,000 条，留出集最多 250,000 条；训练集再按固定种子拆成 80% 拟合、20% 等渗校准，留出集完全不参与训练和校准。引擎单核约 1.1 秒一局，脚本按 CPU 核数并行，本机 8 核完整跑一次约 20 分钟。

正式拟合结果（2026-11-15，逐张牌三家合并，留出集）：

| 难度 | 留出样本 / 正例 | 预测均值 | 实际命中 | LogLoss | 校准 |
|---|---:|---:|---:|---:|---|
| 休闲 | 250,000 / 17 | 0.00786% | 0.0068% | 0.0007198 | 通过 |
| 标准 | 250,000 / 1,980 | 0.78% | 0.79% | 0.0369934 | 通过 |
| 进阶 | 250,000 / 2,617 | 0.97% | 1.05% | 0.0467891 | 通过 |

校准验收用固定预测区间：样本数 ≥1000 的区间，实际值需落在预测均值的 0.75–1.33 倍；全体预测均值与实际值的差不超过 10%。休闲档正例极少，验收额外允许 0.005 个百分点的绝对误差下限，避免十几个正例造成比率抖动。三档都在留出集上通过。

听牌表来自同一批训练局，按「发财数 × 副露数 × 每 6 张牌墙段」计数。单格样本不足 200 时取同一行最近的有效牌墙段，整行不足时用全局先验；这是可信度分层，不是另一套手写概率。

重跑命令：

```bash
npm run coach:fit
node scripts/fit-coach-risk.mjs --workers=8 --sample=500000 --holdout-sample=250000 --epochs=15 --reuse-cache
```

第二条命令复用 `/tmp/coach-risk-cache-20261115-1440-600-500000-250000` 中的数据集，只重做训练、校准和系数生成；换种子、局数或采样上限时会生成新的缓存目录。

### 5.4 标签与「实际放炮」的差别

标签是「有人能胡这张牌」。实际放炮略少（探针 371 对 349，约 6%），因为我们的规则没有「胡优先于碰」，前位玩家可能先碰走。界面统一称「放炮风险」，不另作解释。

### 6.2 生成与运行流程

1. `npm run coach:fit` 先构建 `dist/`，再按 CPU 核数启动 worker；
2. worker 对三档 AI 各打 1440 局训练局和 600 局留出局，按公开特征采样，标签才读取暗手；
3. 主进程合并缓存，训练集按 80/20 拆分拟合与等渗校准，留出集只做最终评估；
4. 评估通过后写入 `src/coach-risk-coefficients.ts`，并记录 `difficulty-<档位>-v1` 策略编号；
5. UI 直接读取生成文件推理，不在浏览器里训练。

系数是对 AI 标定的，AI 策略改了系数就过期。生成文件记录策略编号（如 `difficulty-advanced-v1`），测试比对它和当前编号；它只在有人升了编号时才起作用。改 AI 出牌策略后要主动重跑 `npm run coach:fit`，不能手改生成文件。

对现有文件的改动：

- `web/LocalMode.tsx`：加开关，调用 `useCoach`，把结果传给牌桌。
- `web/components/MahjongTable.tsx`：加一个可选的 `coach` 属性（面板节点 + 每种牌的风险）。联网模式不传。
- `web/components/PlayerSeat.tsx`、`SelfHand.tsx`：接收每种牌的风险，画角标，实现高风险确认。不传时行为与现在一致。
- `web/styles.css`：面板与角标样式，遵守 `DESIGN.md` 的右栏和手牌坞约定。
- `src/index.ts`：导出新模块。

另外两点实现约定：

- **牌效部分沿用 `rankStrategicDiscards(state, seat)`**，它的参数是 `GameState`。它只读自己的手牌和公开信息，由第 7 节的「打乱不变」测试保证。联网要用时必须另写 `GameView` 适配，这不在本期。
- **点评需要出牌前的局面**，用现有 `replayLocalGameSession(session, 步数)` 重算，按「种子 + 局数 + 步数」缓存。不往存档里加字段，刷新后点评仍能恢复。

## 7. 验证

## 8. 已知边界

- 概率是对我们的 AI 对手标定的。真人会藏牌、会放过小牌，数字对真人只能当参考；这也是本期只做本地对局的原因。
- 教练的换牌规则只验证了当步放炮更少，没有验证整局得分更高。此前把风险重排直接加给 AI 的 2400 局 A/B，得分差的 95% 区间跨零。所以教练是「可参考的另一种打法」，不是标准答案。
- 休闲档 AI 随机性大，600 局留出集只有 17 个正例，实际接炮率约 0.0068%。模型会经常显示 0% 或 `<1%`；这表示「按当前 AI 很难接炮」，不表示绝对安全。休闲档适合看相对高低，不适合追求两位小数的精度。
- 样本来自 AI 实际走到的局面，极少见的局面（例如三家都已报嘴）外推可靠性低。
- 本次留出集没有 ≥10% 的预测样本，最高校准区间是 5%–10%；10% 的高风险确认是保守产品阈值，不等于该区间已经被留出集充分验证。
- 拟合缓存是本机 `/tmp` 数据，不入库；换机器后第一次 `npm run coach:fit` 需要重新采样。
