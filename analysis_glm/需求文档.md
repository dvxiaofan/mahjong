# 自定义麻将 · 单机网页版 — 需求文档

> 版本：v0.1 草案（2026-09-04）
> 规则依据：[自定义麻将规则.md](../自定义麻将规则.md)（定稿 2026-09-04）
> 本文档不修改规则定稿，仅做实现层面的澄清与补充；歧义点见第五节，采纳默认值即可开工。

## 一、项目概述

- **目标**：按定稿规则实现可玩的单机麻将游戏：1 名真人玩家 + 3 个 AI 对手，浏览器本地运行，无需服务器、无需安装依赖
- **形态**：单机 + AI
- **技术栈**：纯前端 HTML/JS（ES Modules，无构建工具），规则引擎为纯函数可直接用 Node 跑单测
- **非目标（本期不做）**：联机对战、存档/回放、音效（列为可选项）、排行榜

## 三、核心领域模型

### 3.1 牌（Tile）

- 花色：`wan(万) tong(筒) tiao(条)` × 9 点数 × 4 张 = 108 张；`zhong(红中) fa(发财) bai(白板)` 各 4 张 = 12 张；共 **120 张**
- 角色标记：`fa` 为宝牌；`zhong`/`bai` 为普通字牌（可碰杠入型，无番）
- 发财**永远不参与手牌牌型**，摸到即转移至玩家的「发财区」

### 3.2 牌墙（Wall）

- 洗牌后为 120 张数组，**双向取牌**：
  - 正向（起牌方向）：正常摸牌
  - 反向（墙尾）：发财补摸、杠后补摸
- 荒庄判定：正向摸尽（含被反向取走的牌）后无人胡

### 3.3 玩家状态（Player）

| 字段 | 说明 |
|---|---|
| hand[] | 暗手牌（不含发财），起手 13 张，摸牌后 14 张 |
| melds[] | 碰/杠面子（含类型与来源） |
| faCount | 全场持有的发财数（亮出的，用于点炮资格与番数） |
| baoZui | 报嘴状态（未报 / 已报） |
| score | 累计分数（可为负） |

- 碰后手牌 10 张 + 1 面子；杠同理（杠不额外占手牌位，杠后补摸恢复摸牌节奏）

## 四、功能需求

### 4.1 开局流程

1. 首局：四人掷骰比大小定庄（最大者先起牌）；之后每局上局赢家为庄
2. 洗牌建墙，庄家起，按逆时针轮流起手 13 张
3. 起手/摸牌过程中摸到发财立即触发宝牌流程（4.3）

### 4.2 回合状态机

```
DEALING → TURN(摸牌) ──摸到发财──→ BAO_DRAW(宝牌补摸，可递归)
              │                        │
              ↓←───────────────────────┘
         ACTION(玩家决策：打牌/胡/杠/报嘴)
              ↓ 打牌
         CLAIM(三家鸣牌判定：按本局起牌顺序，谁先起牌谁优先)
              ↓ 无人鸣牌
         下家 TURN
              
胡牌 → SETTLE(本局结算：胡分即时 + 杠分按类结清) → 下一局
正向摸尽无人胡 → 荒庄（不结胡分与任何杠分，已即时支付的补杠分退还） → 下一局
```

约束：

- 报嘴玩家回合被锁死（4.5），UI 需禁用其违规操作（碰/杠按钮、打非摸牌张）
- 补杠后该牌不可被胡（无抢杠胡），但仍触发被碰方即时付 1 分

### 4.3 宝牌流程（发财）

1. 摸到（含起手、正常摸牌、杠后补摸）发财 → 亮牌移入发财区 → **从墙尾补摸一张**
2. 补摸到的仍是发财 → 递归执行本流程
3. 发财 +1 番/张；4 张全在手中也不算杠
4. 报嘴玩家摸到发财：照常亮牌+补摸；**补摸张若可胡则必须胡（算自摸）**，不可胡则该张视为「摸到的那张」，必须打出

### 4.4 鸣牌

| 动作 | 触发 | 补牌 | 限制 |
|---|---|---|---|
| 碰 | 任意一家打出的牌 | 无 | 三家通碰；报嘴禁用 |
| 明杠 | 自己已有暗刻 + 别人打出第 4 张 | 墙尾补 1 张 | 报嘴禁用 |
| 补杠 | 碰过的面子自己摸到第 4 张 | 墙尾补 1 张 | 别人打的不行；报嘴禁用 |
| 暗杠 | 自己摸齐 4 张 | 墙尾补 1 张 | 报嘴禁用 |

- 禁吃
- 同一弃牌的动作及一炮多响：按本局起牌顺序，谁先起牌谁优先，只认第一家
- 杠后补摸可胡 = 杠上开花，按自摸结算

### 4.5 报嘴（固定听口）

1. 前置条件：`faCount ≥ 3` 且当前听牌；**自愿触发**
2. 关键约束：`faCount ≥ 3` 期间**未报嘴可以自摸，但不能点炮**；听牌但未报时仍可正常摸打/碰杠/换听，进听后随时可补报
3. 报嘴后锁死，直到本局结束：
   - 摸到什么打什么（含宝牌补摸张，见 4.3.4）
   - 不能碰、不能杠
   - 自摸到胡张必须胡（无放弃权）；他人点炮可选胡或拒炮（见 5.5 确认结果）
4. 报嘴不可撤销
5. AI 报嘴策略：听牌且无可改进空间（碰杠/换听收益低于胡牌）时报嘴；简单版可「听牌即报」

### 4.6 胡牌与番数

- 牌型：4 面子 + 1 将；碰/杠面子计入；发财不计入
- 胡牌判定基于「暗手牌 + 亮面子」：暗牌数 = `13 − 3×面子数`（摸牌时 +1）
- 番种（可叠加、无起胡番）：

| 番种 | 判定 | 番数 |
|---|---|---|
| 碰碰胡 | 4 面子全为刻子/杠 + 1 将（字牌刻子计入） | +1 |
| 清一色 | 全部为单一花色（字牌是否允许见 5.1） | +1 |
| 发财 | 每张 +1 | +faCount |

### 4.7 胡牌结算

| 场景 | 结算 |
|---|---|
| 自摸（含杠上开花、宝牌补摸胡） | 三家各付 `1 + 番数` |
| 点炮 | 前提：胡牌者 `faCount ≥ 1`；点炮者付 `1 + 番数` |
| faCount = 0 | 只能自摸，无点炮资格 |
| 补杠 | 被碰那家**即时**付 1；荒庄时退还（见 5.4） |
| 暗杠 | 挂账，本局有人胡则终局三家各付 1；荒庄不结 |
| 明杠 | 挂账，终局点杠者付 1；荒庄不结 |
| 杠上开花 | 算自摸 |
| 一炮多响 | 按本局起牌顺序（谁先起牌谁优先）只认第一家 |

### 4.8 AI（3 家）

- 出牌策略：向听数评估，优先打孤张/效率低的牌（V1 简单启发式即可）
- 鸣牌决策：使向听数下降则碰/杠；否则过
- 胡牌：报嘴后自摸胡张必须胡，点炮可拒；未报嘴自摸按规则可胡，≥3财不能点炮
- 报嘴决策：见 4.5.5
- 难度不做分档，同一策略

### 4.9 UI

- 布局：下方为玩家手牌（可点击出牌）；左右上为三家（暗牌背面 + 亮出发财/碰杠区/分数）；中央牌墙余量 + 最新出牌
- 操作：打牌（点击手牌）、碰/杠/胡/过（按钮浮现）、报嘴（条件满足时按钮浮现）
- 结算面板：本局胡牌详情（番种明细）、各家分数变动、累计分
- 荒庄提示、AI 行为有短暂延时与出牌动画（简单过渡即可）
- 字体/牌面：纯 CSS 绘制或字符牌面（🀇 系 Unicode 麻将字符），不引入图片资源

## 五、规则歧义与默认决策

| # | 问题 | 默认值 | 用户确认 | 理由 |
|---|---|---|---|
| 5.1 | 清一色是否允许字牌（中/白）参与？ | **不允许**（有字牌即不算清一色） | A | 主流规则更常见、更严格 |
| 5.2 | 墙尾补摸又是发财 → 递归亮牌+再补摸？ | **是** | A | 「摸到发财就补」应无例外 |
| 5.3 | 同一弃牌/一炮多响的判定顺序 | **按本局起牌顺序，谁先起牌谁优先，之后沿逆时针** | A | 用户明确指定固定起牌优先序 |
| 5.4 | 荒庄时已即时支付的补杠分是否退还？ | 不退 | **B：退**（荒庄杠分一律冲正） | 用户确认 |

## 七、测试计划（M1 重点用例）

1. **胡牌判定**：标准型 / 碰碰胡 / 清一色 / 含中白字牌 / 多解型（如 345+567 拆分）/ 报嘴补摸张可胡
2. **听牌**：单听 / 双面听 / 嵌张听 / 字牌听 / 发财不可为胡张
3. **番数**：碰碰胡+清一色+多财叠加；中白参与时清一色不成立（按 5.1）
4. **计分**：规则文档「结算示例」6 场景逐条断言；荒庄杠分豁免；补杠即时分
5. **宝牌流程**：起手多财 / 补摸递归 / 4 财不算杠 / 报嘴后补摸可胡必须胡
6. **状态机**：报嘴锁死禁止碰杠换听；摸啥打啥；摸到胡张强制胡
