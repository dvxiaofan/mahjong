# 规则引擎说明（GLM）

> 2026-09-04 · 解释「规则引擎」在本项目中的含义、边界与分层关系

## 一、定义

规则引擎 = 与界面无关的「纯规则计算层」，回答游戏里所有**判定类问题**，不画任何画面。对应规划中的 `tiles.js / wall.js / hand.js / wincheck.js / fan.js / score.js / actions.js`，全部是**纯函数**：给输入、返回结果，不碰 DOM、不发网络请求。

## 二、各模块职责

| 模块 | 输入 → 输出示例 |
|---|---|
| `wincheck.js` | 手牌 13 张 → 能否胡？听哪几张牌？ |
| `fan.js` | 胡牌的牌型结构 → 番数（碰碰胡？清一色？+发财数） |
| `actions.js` | 当前局面 → 现在能做什么（可碰？可杠？可报嘴？能不能胡？） |
| `score.js` | 结算事件（谁胡/谁杠/荒庄） → 各家分数变动，含账本冲正 |
| `wall.js` | — → 建墙、正向摸牌、墙尾补牌 |
| `hand.js` | 动作指令 → 手牌/面子区/发财区的状态变更 |
| `tiles.js` | — → 120 张牌的定义、排序、显示名 |

## 三、与另外两层的关系

```
UI 层（ui.js）     → 画牌桌、按钮、动画          ← 只是壳
流程层（game.js）   → 状态机：现在轮到谁、进入哪个阶段
规则引擎（纯函数）   → 判定：这步合不合法、结果是什么、多少分
```

示例链路——玩家点「碰」：

1. `game.js` 知道现在是 CLAIM 阶段、轮到该玩家声明
2. `actions.js` 判定「这张牌确实可碰」（若已报嘴则直接禁用）
3. `hand.js` 执行：从手牌移出 2 张、记入面子区
4. `ui.js` 只负责把结果画出来

分层原则：**UI 永远不发明规则，只调用规则引擎的判定结果**。

## 四、为什么单独抽出

1. **可测试**：无 DOM 依赖，`node --test` 直接跑单测。规则文档的 6 个结算示例、各种胡牌边界用例全在引擎层验证，不用开浏览器手点
2. **规则集中**：报嘴锁死、荒庄冲正（见[规则歧义确认结果](./规则歧义确认结果.md) 2A）这类易错逻辑只写一处
3. **可替换**：以后换 AI、改终端版、加联机，规则引擎原封不动复用

M1 里程碑只做引擎+单测，即先把「规则算得对」钉死，再套界面。
